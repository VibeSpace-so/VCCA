# Product playbook

## When this becomes relevant

- Defining the MVP or roadmap.
- Prioritizing features or requests.
- Designing onboarding and first-user experience.
- Improving activation, retention, or engagement.
- Writing specs or user stories.

## Questions to ask

- What user problem does this solve, and who specifically has it?
- Does this move the next milestone, or is it a distraction?
- What is the smallest version that could test the assumption?
- How will we measure success? Activation, retention, revenue, referral?
- What is the first action a new user must take to get value?
- What happens if we do not build this?
- Are we building for an existing customer or a hypothetical one?

## Common anti-patterns

- Roadmap without a clear goal or metric.
- Feature bloat to keep a prospect happy.
- Building for power users before nailing the core use case.
- Ignoring onboarding and first-time user experience.
- No success metrics for shipped work.
- A/B testing too early with low traffic.
- Copying competitors without validating the same need.

## Decision heuristics

- One metric per milestone. Optimize that.
- Onboarding is a feature. Fix it before adding more features.
- Say no to most feature requests, even good ones.
- Measure activation, retention, and referral before growth.
- Write the one-paragraph press release before building.
- Build what moves the next customer milestone, not what is fun to build.

## Teaching moments

- "Should I build this feature?" → One-question framework: does it move the current milestone?
- "How do I improve onboarding?" → First-action analysis and time-to-value.
- "How do I know users love it?" → Retention, usage frequency, and NPS.
